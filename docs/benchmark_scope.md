# Benchmark scope and task contract

## 统一样本对象

- `ProcessRun`：时间戳、连续过程变量、异常区间、特征名、可选根因。
- `AlarmEvent`：时间戳、标签、激活/恢复状态、优先级。
- `AlarmEpisode`：一次异常或洪泛内的有序事件、类别、可选根因。

时间统一为秒；原始 tag 不跨工厂强行对齐。适配器必须保留原始行号或时间键，且在 data card 中说明：激活/恢复编码、重复/抖振规则、时区、缺失值、工况和标签来源。

## 六条任务轨

1. **T1 报警生成/设计**：过程变量到二值报警。输出 FAR、MAR、AAD 与报警率。
2. **T2 多变量动态阈值**：用正常运行区或物理模型产生条件阈值，同时评价总体检出与边界可解释性。
3. **T3 因果与根因排序**：输出有向边或候选根因排序。根因标签缺失的数据只能用于无监督结构分析，不能计算 Top-k。
4. **T4 洪泛检测/聚类/分类**：输出洪泛时间窗、模板或故障类别；分 closed-set、open-set 和 prefix 三种协议。
5. **T5 next-alarm/洪泛预测**：给定前缀预测下一个 tag、未来集合或洪泛发生，报告准确率、提前量和误报。
6. **T6 运维可视分析**：生成 KPI、bad actor、相关图和洪泛图；首期不设视觉美学排行榜，只验证统计量和溯源一致性。

## 实现成熟度

- **A / runnable**：本仓库实现、单元测试通过、配置可调用。
- **B / protocol-ready**：任务、输入输出和指标完整，但论文代码或受限数据尚未接入。
- **C / evidence-only**：只有论文/数据元信息，不宣称可复现或 SOTA。

正式 leaderboard 只接受 A 级方法和可审计数据；B/C 级用于规划复现工作。
