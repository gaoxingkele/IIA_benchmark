三个原始 CPU 队列的完整范围恢复 v3
==================================

本轮恢复熵正则 FM、Pi-Transformer 和 MOMENT 三个原始队列的调度，保留全部 1,317 条已登记记录。105 / 1,140 / 72 是各队列总记录数，包含既有完成、失败和待运行记录，不能称为本轮新增完成实验。

三条队列与已恢复的 175 条 CPU 基线队列使用同一个真实串行资源锁：experiments/runs/fm_bounded_strict_baseline_cpu.lock。本轮不增加该通道模型并发；原有 CFM、RCGAN、TimeGAN、MaelNet、BRITS 训练进程不停止，原 GPU 互斥和阶段前置条件不变。

全部原始队列、模型、数据、运行命令、结果判定和预算未修改。原 CPU 线程分别为 4 / 2 / 2。复用原始控制器 main 与 guarded_factory 的代码对象，仅在原紧急提交内存保护条件上增加进程树 RSS / private 内存上限。物理可用内存启动线加强为 16 GiB，原提交内存启动线 32 GiB、紧急保留线 16 GiB 和轮询间隔保持；RSS 上限 10 GiB、private 上限 12 GiB。资源不足时继续等待，不能降低训练预算来通过保护条件。

切换前通过实际 PID、创建时间、完整命令、原配置和队列 SHA、当前请求任务、无模型子进程以及无分离任务进程核验，仅结束空闲的调度器。保留每个旧状态快照和交接回执；新控制器的实际进程身份和状态见 actual_execution_observations.json。初次观察三个新控制器均因原 32 GiB 提交内存条件等待，不能称为三个模型已实际开跑。

熵正则 FM 的前一 SMD / SF2M flow-only seed1107 已独立核验原 result.json、模型和分数 SHA，完整任务终止回执 exit0，无资源保护中止。Pi-Transformer/source_runtime/PSM seed1105 的前一尝试被原提交内存保护中止，exit1；保留资源回执、原 failure.json 和原输出，不覆盖检查点，也不计完成。原控制器会保留这种失败项，这些仍须独立恢复，不能因新的控制器已启动就算完成。MOMENT 的已下载权重零样本评估也不等于论文重新训练。

验证：41 项相关测试通过（12.13 秒）；三个实际冷探针保留全部队列记录，未导入 numpy/torch。测试验证串行锁、原 main/worker 调度代码对象、原全部线程与队列绑定、保护边界，以及拒绝 PID 复用、活跃模型、错误源和非空待运行输出。原已存在的空 Pi 日志可以继续 append，非空日志或任何模型文件必须保留。

没有新增可发布的性能行，没有新增 canonical 训练种子槽。最新数值表仍为 all_algorithm_dataset_metrics_v26，各协议和逐指标采集时间保留。初次观察原六个实际模型进程 CPU 时间均在增长。
