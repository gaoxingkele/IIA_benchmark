# 完整图像训练执行恢复：Windows 路径与显存重计算

本轮捕获两个真实终止事件：主 Flow Mismatching 图像训练在首次记录环境时，223 字符文件路径加上 37 字符 UUID 临时后缀达到 Windows 260 字符限制，报 FileNotFoundError；WT 完整 batch32 训练触发原显存紧急门槛，保护器终止子进程。两个原控制器和子进程均已不存在，失败目录、日志、terminal 和既有配置已保留。两者均未完成任何训练 epoch，不能继续把它们描述为活跃训练。

修复采用显式 Windows extended-path 文件操作，并保持原临时 UUID、原子替换、完整检查点、两个滚动槽和不可变快照硬链接语义。实际 260 字符临时路径写入和快照保留测试通过，不需要改原始数据位置或文件名。

显存方案仍使用完整 45,289,539 参数骨干、54 个原生 ResBlock 和 29 个 AttentionBlock，通过原生块选项配合明确 use_reentrant=False、preserve_rng_state=True 做激活重计算。下载源码未改写。最初的默认 reentrant 候选未通过原有梯度/多步一致性约束，源码和失败测试已保留；改用 nonreentrant 后，FP32/BF16 的三步原生优化器、损失、随机状态、梯度和参数测试通过，原容差未放宽。检查点机制参考 [PyTorch 文档](https://docs.pytorch.org/docs/2.14/checkpoint.html)，本地实际训练包仍保留冻结的 Torch 2.13，未升级共享环境。

6 项测试通过，0 跳过；完整模型参数和状态字典在 meta 设备核验，CPU 数值夹具验证实现。它们不能证明实际 GPU 容量或完整训练性能。因此另登记两个真实 CUDA 容量任务，分别用原 WT 与 FM 目标、完整32×3×128×128批次、原正常训练数据、完整原模型和优化器执行前向/反向/更新及完整检查点写入重读。这里只测一批是明确的硬件容量探针，不替代原训练、不计训练种子或性能结果。
