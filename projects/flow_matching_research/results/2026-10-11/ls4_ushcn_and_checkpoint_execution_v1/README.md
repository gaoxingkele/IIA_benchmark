# USHCN 原始任务数据与完整检查点重推断

本轮完成作者 USHCN 预处理数据获取、五折划分重建和全量原生加载核验。尚未产生 USHCN 的完整 500 轮训练结果；全项目实验仍未完成。

## 完整数据与划分证据

- 原始来源：[GRU-ODE-Bayes 作者仓库](https://github.com/edebrouwer/gru_ode_bayes)，固定提交 `ddd0b34e884dbee1c09b6a3927d1e9ab10443af8`。下载完整 CSV、处理脚本、划分脚本、许可证和相关实验源码，共 12 项。
- 使用 aria2c 经配置代理下载；逐文件核验大小及上游 Git blob SHA1，再记录 SHA256。原始文件位于 `F:/aicoding/IIA_Data/public_datasets/flow_matching/ls4_native_ushcn_v1/raw/`，没有覆盖或改写。
- CSV 共 **350,665 行、1,114 个序列、5 个变量、386,068 个观测值**，时间范围 0–200，缺失率 77.9808%。每一行的观测掩码、缺失占位、ID/时间唯一性和有限值均已检查。
- 作者提供的五个划分目录实际是私人服务器路径链接。将链接保存为文本，没有跟随链接，也没有声称获得历史作者划分文件。
- 在锁定的 LS4 Python 3.10 环境中执行未改写的作者五折生成脚本，保留种子 432。每折的原始位置划分为训练 801、验证 201、测试 112。

原始 CSV 的 ID 有 9 处空缺，最大 ID 为 1122。原脚本直接用 `np.arange(N)` 作为真实 ID，导致 9 个真实序列被遗漏，同时生成 9 个不存在的 ID。因此分别保留：

| 分支 | 行为 | fold 0 原生加载的训练／验证／测试序列 |
|---|---|---|
| source_literal | 保留作者原样位置 ID | 795／199／110 |
| id_corrected | 将原位置划分映射回真实 ID，保持同一随机分配和全部原数据 | 801／200／112 |

四个原始序列 `194、298、626、656` 没有时间 ≤150 的观测。原加载器会从验证／测试中过滤这些序列，此行为保留并记录；没有补造观测，也没有从训练分支任意删除原序列。其他折的实际数量见完整报告。

## 原始加载与评估协议

[全量加载报告](../ls4_native_ushcn_loader_v1/original_loader_audit.json)覆盖两个分支 × 五折 × 插值／外推，共 **20 个组合、360 个原始批次**。逐序列比较了全部原始值、时间和掩码；独立核验了训练集加验证前缀拟合的归一化参数及全部批次覆盖。两种原始 YAML 都是 batch 64、500 epochs，每个组合完整训练预算为 8,000 次优化器更新。

另有两个需要在结果比较时保留的源代码行为：

1. `custom_collate_fn_climate` 仅使用 `path`，没有使用 Climate 预留的 `val_samples`。因此原测试加载并不是直接评估时间 150 之后预留的三条观测。fold 0 原样／修正分支分别有 330／336 条这样的预留记录，均未进入该原始 collate 的目标。
2. 原插值配置未额外遮盖输入，完整原加载核验确认输入和预测目标重合。原外推配置则沿原 batch 时间网格切分。没有将这些诊断称为严格独立测试性能。

发布 CSV 上游处理脚本还包含划分前的全体数据标准化；当前下载的是作者已经发布的预处理 CSV。历史作者划分、论文评估口径及作者等价性仍需进一步核对。
