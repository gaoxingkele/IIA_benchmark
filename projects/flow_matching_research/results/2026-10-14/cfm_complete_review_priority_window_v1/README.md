# 原训练自然释放点的完整核验窗口

已完成的源训练进入最终核验后，核验进程需要原定30GiB空余提交；原训练家族的下一任务只需原定22GiB，可能先重新占用内存。为推进已登记的完整模型证明，新协调进程在**同一个原byte0训练家族锁**排队，只在当前模型自然训练／评分结束并释放锁后获得窗口；当前训练与其父进程未停止、重启或修改。

排队使用原完整285训练队列的原22GiB提交／12GiB物理／16GiB紧急提交策略，取得锁后完整核验仍要求原30GiB提交、16GiB物理、16GiB紧急提交及原2GiB RSS／4GiB private上限。原生重放、独立审核、模型、解算器、原始网格、训练预算和所有核验参数均不变。既有原核验控制器自行调度数值子进程，新协调器不执行或改写数值工作。

目标为GP conditional400／Sine seed1106、1107，以及两个BB literal400／Sine seed1104、1106的完整规范证明。两条全285路由及原45篇／681方法消融／273数据任务范围都保留；不从成功子集替代缺失任务，不增加训练种子。

窗口最多900秒，仅是调度锁期限，不是模型或核验的计算预算。以下条件会释放调度锁：四个证明全部完成、对应源／核验明确失败、紧急提交余量不足、窗口期限到达，或不满足原核验启动门限且没有实际数值核验进程运行。检查实际核验的PID、创建时间、完整命令和`--worker`／`--review-worker`，不会用空闲控制器状态冒充数值工作。在真实已获准核验使用其内存期间可以继续保留窗口，其原资源保护照常生效。窗口释放不终止任何数值任务，原下一次完整训练继续使用自己的原资源门限。

实际启动身份为PID36888、create_time1791937937.715254，完整命令及原门限见 `actual_review_window_controller_launch.json` 和 `actual_original_guard_and_pending_target_preflight.json`。源GP seed1107当时已到366/400 epoch，仍由原科学进程训练；协调器只等待下一次自然锁释放。
