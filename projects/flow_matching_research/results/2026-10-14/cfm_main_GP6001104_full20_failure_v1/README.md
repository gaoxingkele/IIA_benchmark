## seed1104：完整诊断含一个失败

原训练为 600 epoch／93600 updates，批量258；保存模型 SHA256 为 `defecae0d2ca4959ac71f4eccc3d8037b78890de13ce36d94cedd2703e1ca8b5`。原评分完成12／20条后报 `AssertionError: underflow in dt 0.0`，未触发资源终止。

在模型尚未启动时，适配检查发现覆盖常量计数和收据关键字处理遗漏。修改前的源码、测试、配置和失败 XML 完整保留于 `preserved_pre_execution_*` 及 `preserved_pre_registration_validation_failure.xml`。修正后重新绑定源码校验和，再启动唯一一次原生诊断；此后没有改动运行或冻结的源码、模型、容差及资源限制。

诊断恢复并核验保存模型的完整预算、600条有限训练损失和全部有限权重。原生求解器、500点网格和观察器数值代码沿用已有流程，仅适配实际20条轨迹覆盖和诊断文件名。资源门限仍为原配置的30 GiB提交内存余量，未降低。

全部20条轨迹已尝试：19条完整有限输出，轨迹68失败。独立复核检查全部10000个坐标、每条轨迹收据、原时间／真值／编号、失败掩码及成功轨迹MSE。完整原始MSE仍为空，不以19条成功样本替代20条完整指标。

轨迹68初值为 -2.5142768297757083，落在该种子训练观测范围 [-2.9245717312722674, 2.9634863441018364] 内。有限速度最大值3.3563676213086046e38，随后先出现非有限速度、再出现非有限状态；原求解器在约5.23e-6时刻报步长下溢。具体训练原因和作者代码错误尚未证实。

诊断退出0表示取证完成，`original_benchmark_scoring_complete` 仍为false。没有追加训练、调松求解器设置或失败后反复尝试。
