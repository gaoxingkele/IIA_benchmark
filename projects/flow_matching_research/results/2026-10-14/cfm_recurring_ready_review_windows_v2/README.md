# 全285原任务的可重复完整核验窗口

**此v2已退休，保留为诊断历史。** 实际核对发现为导入指纹函数而加载完整原数值模块及科学依赖，空闲private约1.608GB。控制器在未持有家族锁、只有console子进程时，经suspend前后两次PID／创建时间／完整命令与状态验证，只退休该空闲元数据进程；科学模型未停止。原源码、配置、启动记录、实际内存与安全退休证据全部保留。v3改为只加载原指纹函数AST，保持完整285路由、全部准入／保护门限和调度规则；见相邻 `cfm_recurring_ready_review_windows_v3/`。

一次性窗口已在原门限下完成积压的模型证明，并自然释放训练家族锁。后续源模型仍可能比需要30GiB空余提交的核验更快重新取得内存，因此新增可重复协调器覆盖两条完整285路由：原主队列及两个已登记BB完整重跑的补充队列。

协调器只使用已正常训练和评分的源结果：源终端exit0、complete=true、资源未中止、原模型指纹匹配、全部原epoch与optimizer updates、完整原网格形状、非smoke且未宣称作者等价。已拥有规范完整证明的模型排除；两个重跑别名按原规范ID处理，不增加种子。核验仍由原控制器与原数值子进程执行。

每次在同一个原byte0家族锁排队，当前模型自然结束后取得窗口；此时重新选择当时已完整完成而尚未核验的源任务，**不等待其他尚未训练的种子**。源控制器在释放锁之后才发布终端receipt，允许最多五次2秒metadata等待，期间必须满足原核验门限。既有独立控制器继续按原30GiB提交／16GiB物理／16GiB紧急提交及原RSS/private上限调度真实数值核验。没有降低门限、缩短预算／网格、改模型、解算器或容差。

每个调度窗口最多900秒。完成已就绪任务、对应源／核验失败、紧急提交不足、窗口到期，或不满足原核验准入且没有经PID／创建时间／完整命令确认的实际数值核验时，释放锁。释放不停止任何数值任务；原下一个训练继续自己的原完整预算与准入规则。没有新就绪来源或实际原模型时，协调器不占有家族锁。原源控制器真正终止且没有就绪核验时，协调器退出，但不将全研究或全285任务宣称完成。

启动时存在两个就绪而未闭合的原任务：主文GP conditional400／Sine seed1103、1104。启动身份为PID456、create_time1791939210.7269375，完整命令、原门限与缺口保留在本目录及配置中。原源模型seed1105仍正常训练；新增进程不停止、重启或热修改它。

10项相关验证通过，包括只有完整预算、完整网格和成功原源凭证能够进入窗口、smoke与资源中止拒绝、两条完整285规范范围及原门限保持、资源不足时释放、真实已准入数值工作不能被空闲状态替代、原Windows字节锁互操作与排队优先边界。见 `validation.xml`，这些测试不属于模型性能结果。

配置入口：`configs/runtime/fm_cfm_ready_complete_review_windows.v2.json`。过程状态及各次调度释放receipt：`experiments/runs/fm_cfm_recurring_ready_review_windows_v2/`。本任务改进调度时序，保持45篇论文、681项方法基线消融、273项数据任务及全部285个CFM任务的科学范围；全部研究仍未完成。
