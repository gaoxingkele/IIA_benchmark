# 两个 BB400 的实际入口修正与第 138 个完整 CFM 核验结果

两个主文 BB paper-literal／Sine／seed1104、1106 原先因 Windows 元数据替换权限错误退出，未保存模型。随后原重跑包装器取得家族锁，但在训练前调用不存在的 `main()`，两次均以 `KeyError: 'main'` 退出。原始 worker 将命令行解析直接写在 `if __name__ == '__main__'` 中。旧验证检查了训练函数字节码，却没有覆盖真实模块入口；失败原日志、终端凭证和状态完整保存在 `preserved_actual_entry_failure/`。

新 v2 包装器执行原始模块入口的原样 AST，并继续使用原始 `run`、`complete` 及其他数值函数字节码。仅元数据发布沿用独立临时文件与有界权限重试。新目录注册两次完整 400 epoch／6400 updates／20×500×1 的训练，不给未保存的旧 epoch 任何完成抵扣。完整 285 个原注册槽位、同一字节家族锁、22 GiB 启动提交余量、12 GiB 物理余量、16 GiB 紧急提交余量、CPU 线程数 1 均保留；资源余量在锁取得后再次检查。

在实际注册的 `.venv/cfmts-author-py312/Scripts/python.exe` 中，worker `--help` 与生产控制器 `--probe-only` 均正常结束；19 项验证通过，覆盖实际模块入口、无 `main` 的原始 CLI 分派、原数值函数字节码、全预算注册、完整重放路由、实际 Windows 字节锁互操作和资源门限。注册前一次归档失败造成缺少配置文件，失败 XML 和当时注册源码亦保留；修复归档文件名及配置字段后才启动。测试与探测不算模型实验性能。

修正后的生产控制器 PID25624、create_time1791934483.0933013 与核验控制器 PID40572、create_time1791934483.120525 已按真实 PID、创建时间和完整命令重核。生产控制器在原家族锁内核队列等待；新核验控制器保留全部 285 路由，接纳主队列实际 138 个完整证明，并只调度这两个新执行来源。两次新 BB400 训练尚未完成。旧输出、旧配置／脚本和实际在训练的其他模型均未覆盖、修改或中断。
