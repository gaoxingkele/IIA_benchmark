# Pi 实际训练日志的时间单位核验

当前完整 PSM／causal-axis-repaired／seed42 任务的科学进程 PID22432、create_time1791927002.4746633 按真实创建时间与完整命令确认存活。原队列预算为 3 epoch，每 epoch 518 次更新，共 1554 次优化更新，132382 个 stride-one 训练窗口，batch256、window100。原训练代码、资源门限、配置和训练预算未修改，未停止或重启实际模型。

发现的是监测日志错误：原 `AnomalyDetection.train` 将 `iter_count` 设为 1 且从不递增，每 100 次更新打印一次 `(time.time() - time_now) / iter_count`。这使同一 epoch 内连续打印区间的“秒/次更新”及基于它计算的剩余优化时间放大 100 倍。独立工具通过原源码 AST 检查恒定计数器、100-update 打印分支及打印发生在当前 `optimiser.step()` 之前，未修改冻结源码。

冻结日志最后一个可用的同 epoch 区间为 epoch2 第5个打印边界：

| 项目 | 原日志 | 经源码核验的解释 |
| --- | --- | --- |
| 区间时间／更新速度 | 862.2668 s/iter | 100 次更新的区间耗时；约 8.622668 s/update |
| 剩余优化时间 | 463037.2704 s | 按同一已观测区间速度估计约 4630.372716 s |
| 优化更新进度 | 未单列 | 至少完成 1017/1554 次；尚未完成训练 |

原日志的模型更新与完整 epoch 输出证明 epoch1 已结束，其余记录属于 epoch2。打印发生在当前优化步骤之前，因此计数下界扣除尚未执行的该次更新。每个 epoch 的首个打印区间可能包含初始化、前一 epoch 的尾段及验证时间，全部排除，不直接除以 100。报告分别保存最后打印边界和最后可用的同 epoch 区间。

修正数字是条件于已观测区间速度的剩余优化时间估计，不含未来验证、保存、测试或其他队列等待，也不保证最终完成时刻。此结果不表示性能优劣、完整模型复现、作者等价、严格 TAB 或新增训练种子。原 3 epoch／1554 updates 及完整 1140 项 Pi 队列范围继续保留。

5 项测试验证原恒定计数器、递增计数器不能套用此修正、同 epoch 区间、跨 epoch／尾段排除、优化步骤计数下界及重复日志／超预算拒绝；见 `validation.xml`。真实原日志字节快照保存在 `original_stdout.log`、`original_stderr.log`。源码、配置和快照 SHA256 固定在 `configs/reproducibility/fm_pi_actual_training_log_units.2026-10-14_v1.json`，完整核验结果见 `actual_source_and_live_worker_timing_unit_audit.json`。

这个具体日志缺陷只对本地已固定的 Pi 历史镜像与修正轴 runtime 成立，不等于对应期刊版本也存在相同问题。原始代码出处与身份保留在被冻结的 Pi 任务队列及 runtime 源文件中，期刊版等价尚未认证。
