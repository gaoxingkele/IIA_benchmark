# 500项完整检查点复核的状态写入故障恢复

原复核调度器PID35008已退出。保留的完整报错显示，它在替换status.next.json到status.json时收到Windows WinError5“拒绝访问”。这个记录定位了失败操作，不能单凭该记录认定具体哪个程序持有文件。原状态为等待训练完成，没有活跃数值子进程，没有任何复核尝试目录、数值产物或已完成/失败复核计数。

独立恢复入口在确认旧PID及创建时间所指的进程已不存在、原冻结输入哈希不变、没有任何数值尝试后启动。它在新的元数据解释器中，仅替换原控制器的status.json写入函数：为每次发布创建独立临时文件，对Windows错误5/32/33最多尝试80次，每次间隔0.1秒；写入内容只计算一次。达到上限仍会失败并保留旧状态及临时诊断文件。其他错误立即传播，其他路径的写入全部委托给原函数。

该重试只涉及状态文件重命名，不重试训练、推理或独立数值复核。原500个唯一模型、源文件和配置、资源保护、2e-6公式容差、2e-12指标容差与逐字节数组比较均未修改。数值子进程继续使用原模块和原运行配置，不继承元数据解释器内的替换函数。旧报错、旧状态、待替换文件及启动记录均按原字节封存。

10项检查通过，覆盖访问冲突后相同内容重试、重试耗尽保留证据、其他错误立即失败、非状态写入不重试、PID身份核验、活跃子进程/已有数值尝试拒绝恢复，以及真实500项冻结契约与哈希核验。真实新控制器PID33020及创建时间已核实，恢复为等待原始完整训练完成，错误日志为空。
