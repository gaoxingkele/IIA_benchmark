# TAB 资源中止缺口的逐指标保存与独立恢复版本

原始 TAB 878 项任务、2057 组标签口径继续保留。新版本仅接收原控制器已记为失败、实际守卫证明因资源阈值中止、且原子进程已终止的缺口；数值函数异常或模型失败不会自动进入恢复。原 TAB 控制器继续执行其他已就绪的种子，没有停止或修改原计算。

保留全部原始 6 个分数指标、15 个标签指标、每组实体标签 201 项调用、3 个验证阈值、10 个原诊断阈值以及完整 VUS 范围与 250 阈值网格。恢复仍复用原完整工作流和数值函数，只在函数调用边界增加持久保存。每个单元格保存原标签／分数实参、函数文件、源检查点与分数证据的哈希；输入、源函数、身份或缓存结果变化时拒绝复用。有限值、未定义值、原异常与警告全部保留，不补零、不挑选有利结果。

逐指标记录使用临时文件、flush、fsync 和原子改名，不覆盖已有记录。中间单元格只是检查点，不能独立冒充通过资源守卫的成绩；只有完整实体工作流结束并通过新的实际守卫后才认证该实体。每个缺失实体在此版本只安排一次新尝试，发生新中止或错误时保留证据，不自动重复。旧版已通过守卫的完整实体直接引用，不计作新独立重复。

准入提交余量从原 28 GiB 加强为 32 GiB，并要求连续 6 次、间隔 5 秒的稳定观察；原物理内存门槛、16 GiB 紧急线、3/6 GiB RSS/private 上限及审计锁均保持。未降低保护线，也没有修改模型训练预算、指标定义或积分网格。

21 项验证通过：模拟中断后保留已完成 7 项、继续计算其余 194 项，并验证完整 201 项再次读取不会重复执行；还覆盖完整 804 项实体调用与保存工作流、缓存篡改拒绝、稳定观察重置和旧成功片段引用。完整工作流用例发现 Windows 深目录下临时文件名过长的问题，已改用同目录的短临时名；失败 XML 和哈希保留，最终 21 项通过。合成探针仅验证恢复与数值不变，不能作为真实数据集成绩，没有生成伪造的科学守卫。

存档时恢复控制器实际存活，已核验并引用原种子 1103 的六个成功实体，但因不足加强后的 32 GiB 稳定余量，尚未开始 A-7 的新尝试。该资源中止缺口尚未完成。原 TAB 控制器仍处理种子 1104，来源、输出及失败记录保持分离。
